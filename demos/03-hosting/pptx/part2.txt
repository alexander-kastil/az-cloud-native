# Graceful shutdown for message consumers
### In-flight messages settle before SIGKILL
- A change to the **template** creates a revision; app-wide settings do not
- SIGTERM, then `terminationGracePeriodSeconds` (default 30 s), then SIGKILL
- Set the grace period longer than `HostOptions.ShutdownTimeout`
- `StopProcessingAsync` stops intake and waits for in-flight handlers
- Settle each message before the handler returns

# Following one booking with KQL
### One query returns every row of the booking
- `POST /shipments` with tracking number `CL-2026-000142` returns 201 Created
- shipping-api writes to `shipments` and sends `ShipmentBooked` to `shipment-events`
- `ShipmentBookedProcessor` in tracking-service writes the booking to `tracking`
- `booking-trace.kql` takes the **OperationId** of the latest shipping-api POST
- It unions `AppRequests`, `AppDependencies` and `AppTraces` in time order

# Takeaways
### What to carry into reliable messaging with Service Bus
- Declare the environment in the AppHost and let `aspire deploy` build the rest
- Read secrets and settings through a **managed identity**, so no password is stored
- Release behind a **traffic split** and keep the previous revision for rollback
- Give consumers a grace period longer than the host shutdown timeout
- Run Dapr actors on AKS, and join one scan's telemetry by `OperationId`
