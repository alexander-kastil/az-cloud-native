# Declaring and wiring resources
### WithReference passes the connections, WaitFor orders the startup
- Each builder call adds a **resource**; the generated `Projects` type catches a wrong reference at compile time
- `WithReference` hands a service the connection details as environment variables
- `WaitFor` holds a service until its dependency is Running; client retries still apply
- `aspire run` starts every resource and the dashboard; `--isolated` runs a second copy

# Parameters for secrets and settings
### AddParameter keeps the routing API key out of source
- `AddParameter` declares a value the AppHost needs but does not hard-code
- `secret: true` marks it as sensitive, such as the routing service's API key
- Aspire reads **environment variables** first, then configuration files and user secrets
- With no value anywhere, Aspire asks the developer on the first run

# The ServiceDefaults project
### One call gives a service telemetry, resilience, discovery and health checks
- Each service references ServiceDefaults and calls `AddServiceDefaults` once
- **OpenTelemetry** wires logs, metrics and traces; `OTEL_EXPORTER_OTLP_ENDPOINT` sets the target
- Every factory `HttpClient` gets the resilience handler and **service discovery**
- `MapDefaultEndpoints` maps `/health` and `/alive`, in Development only

# The standard resilience handler
### Five stages between the booking code and shipping-api
- `AddStandardResilienceHandler` adds retries, timeouts and a circuit breaker
- The **total timeout** of 30 s spans every retry; each attempt gets 10 s
- Retries replay requests, so the booking call to shipping-api must be **idempotent**
- Request clients through `IHttpClientFactory` or a typed client to get the handler

# Hosting and client packages
### The AppHost declares the resource, the service consumes the connection
- A **hosting package** runs in the AppHost and adds calls such as `AddAzureServiceBus`
- `aspire add azure-service-bus` adds the package and records its version
- A **client package** registers the SDK client with its health checks and OpenTelemetry
- `connectionName` must match the AppHost resource name: the name is the contract

# Local emulators and Azure deployment
### The same messaging resource and client code on both lanes
- `RunAsEmulator` swaps the Azure resource for a local container during `aspire run`
- Service Bus runs with a SQL Server companion, Cosmos DB as vNext Linux emulator, Storage as **Azurite**
- Every emulator needs a **container runtime**; the first run pulls the images
- Without `RunAsEmulator`, Aspire provisions the real resource and the client code stays the same

# Traces across HTTP and Service Bus
### One trace ID follows the booking from shipping-api to tracking-service
- HTTP calls carry the W3C trace context in the `traceparent` header
- Service Bus carries it in the `Diagnostic-Id` property of each message
- The waterfall adds a span per step; the **longest bar** names the slowest step
- The defaults switch on the Azure SDK spans and register the `Azure.*` source
