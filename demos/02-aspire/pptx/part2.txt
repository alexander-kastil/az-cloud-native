# MCP access and the standalone dashboard
### Coding agents read the telemetry, any OTLP app can send it

# Gate tests
### A fixed test proves each step that an agent builds
- A gate proves one step is done, checked from outside the code the step changes
- Write the gate first; `AGENTS.md` tells the agent to leave the test project unchanged
- `[Trait("Gate", ...)]` lets `dotnet test --filter` run exactly one step's gate
- A gate takes the smallest form: a `curl` call, a unit test or a full AppHost test

# Takeaways
### What to carry into the hosting module
- Describe the system once in the **AppHost**; one command starts it in order
- Opt every service into **ServiceDefaults** with one call
- Keep `connectionName` equal to the resource name; emulators run the same code
- Follow one booking as one **trace** across HTTP and Service Bus
- Write **gates** before the agent writes code, and wait for health in every test
